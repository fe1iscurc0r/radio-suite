# ADR-2026-10-24：radio-suite 选型 C++20 + Qt 6（Widgets + QOpenGLWidget）

- 状态：**已接受（M0 spike 通过，go）** · 决策人：师傅 BG5GXO 2026-10-24 拍板（工单 268 §一） · 本 ADR 记录论证与实测证据
- 背景与备选：Rust + Tauri（上一版工单 `archive-268-v2-*` 的方案）、Dart + Flutter（APRSLocus 同栈，调研见 `docs/research/aprslocus-2026-10-24.md`）

## 1. 三栈对照（结合本次 spike 实测）

| 维度 | C++20 + Qt6（选定） | Rust + Tauri | Dart + Flutter |
|---|---|---|---|
| 瀑布/频谱性能 | **OpenGL 纹理滚屏 + GLSL colormap**，spike 已实测（R8 环形纹理 + REPEAT 滚动 + 着色器上色，谱线 GL_LINE_STRIP） | 强（WebGL，但走 DOM/IPC 合成） | 中（CustomPainter/Skia） |
| 常驻内存 | 实测 **135–163MB**（Qt Widgets + GL 上下文；含 D3D 着色器编译器占用） | ~60MB（估） | 200MB+（估） |
| 分发体积 | 实测 windeployqt 后 **78MB**（含 opengl32sw/D3Dcompiler 可裁剪项） | ~10MB | 30–60MB |
| 串口/UDP/音频/SQL | QSerialPort / QUdpSocket / RtAudio / QtSql 全家桶，一个生态 | 拼 crates | 可用但非强项 |
| SDR 领域对照系 | SDR++ / Gqrx / SDRangel 同栈 | 少 | 无（APRSLocus 是孤例且其渲染层不可复用） |
| 施工风险（AI 写码） | 高（编译/链接错误多）——**已用 spike 实测对冲：MSVC 一次编译全绿，23 用例全过** | 中 | 低 |

**为什么押 C++（结论）**：瀑布是这套软件的门面，性能上限与领域对照系都在这边；spike 的实际施工
体验（首日从零到双构建全绿 + GUI 冒烟通过）证明 Trae 风险可控——这是本 ADR 最重要的一条实证。

## 2. GLM 的定位：只做数学，不做框架

GLM（MIT，header-only）**仅承担矩阵/向量运算**（若 M2 的瀑布坐标变换需要）。界面、事件循环、
渲染框架全部是 Qt；两者职责不重叠，GLM 不出现在构建依赖里直到真正需要。当前 M0/M1 不引入。

## 3. Qt LGPLv3 与本仓 AGPL-3.0 的边界

- 本仓 AGPL-3.0-or-later（LICENSE 全文）；Qt 6 开源版主模块 LGPLv3，部分模块 GPLv3——
  LGPLv3 库可被 AGPL 项目正常使用，合规路径为**动态链接**（spike 已按此构建：windeployqt
  产出的 DLL 随包分发，78MB 目录即动态链接证据）。
- 若未来为单文件分发改静态链接：按 LGPLv3 §4 提供可重链接目标文件，或按 §3 转 GPLv3 再依
  AGPLv3 §13 并入；两条路都必须回写 `NOTICE.md`，禁止「静态链接还按 LGPL 走」。
- 不引入 Qt 商业模块；打包脚本（M5）必须走 windeployqt/linuxdeploy/macdeployqt 的动态链接路径。

## 4. M0 spike 实测记录（2026-10-24，本机）

环境：Windows 11（DPI 150%）、i7、MSVC 14.44（VS2022 BuildTools 自带 cl/vcvars）、CMake 3.31
（VS 自带）、Ninja（VS 自带）、Qt 6.8.3 msvc2022_64（aqtinstall 经清华镜像安装到 D:/Qt，仓库内
**零 Qt 路径硬编码**，configure 时传 `CMAKE_PREFIX_PATH`）。

三项验收：
1. **CMake 模块化工程**：`BUILD_GUI=ON`（MSVC+Qt6.8.3）与 `BUILD_GUI=OFF`（零 Qt headless）
   各配置/编译一次，均 0 error；core/dsp/app/tests 四 target 独立。
2. **core 协议闭环**：`tests/fixtures/*.hex` 由 `vendor/rsba1-core`（MIT 参考实现，IC-705 真机
   验证 2026-08-18）生成，C++ 用例逐字节对照（含工单示例帧 `FE FE A4 E0 03 FD`）——
   **23/23 用例全绿**（GUI 与 headless 两个构建目录各跑一遍）。
3. **Qt 窗口 + 合成谱**：MainWindow 显示频率（14.270000 MHz）/模式（USB/1）/S 表/PTT（绿键），
   2048 点合成谱经 pocketfft → 1024 显示列 → QOpenGLWidget R8 环形纹理滚屏 + GLSL colormap +
   GL_LINE_STRIP 谱线；UIA 自动化枚举 18 控件全在位，1280×720 截图存
   `docs/screenshots/m0-spike-1280x720.png`。

**三个数字**（工单要求）：
| 指标 | 值 | 口径 |
|---|---|---|
| 冷启动到窗口可见 | **2.38 s**（首启含磁盘缓存冷）／热启动 0.52–0.94 s | windeployqt 打包目录，`--mock` |
| 空载 RSS | **135.7–162.9 MB**（多次测量区间，含 GL 上下文） | 窗口稳定 3–20 s 后 WorkingSet |
| 打包后目录体积 | **78 MB** | windeployqt 默认；`--no-opengl-sw` 等可裁剪，M5 细做 |

**已知限制**：本机无 WSL，Ubuntu headless 编译未在本机复跑（CI workflow `.github/workflows/ci.yml`
三平台 matrix 已就位，推仓后自动验证 ubuntu-latest BUILD_GUI=OFF）；windows CI 用
install-qt-action 装 6.8.x。这是本 ADR 唯一的未闭环项，不构成 no-go：headless 语义（零 Qt 依赖
编译 core+dsp+tests）已在 Windows 侧以 `BUILD_GUI=OFF` 等价验证。

> 2026-10-26 口径更正：上述“零 Qt”仅是当日预期，不是当前事实。现在 `BUILD_GUI=OFF`
> 只表示不编 Qt Widgets；CI-V、UDP、session/总线测试仍使用 Qt6 Core/Network，
> Linux 音频还需要 ALSA。README 与顶层 CMake 描述已按现状修正。

## 5. 依赖钉定与离线策略

pocketfft @ `4d865cba`（mreineck/pocketfft，BSD-3，FetchContent）、Catch2 @ `v3.7.1`（BSL-1.0，
FetchContent）。本机 github 直连不稳时用 `FETCHCONTENT_SOURCE_DIR_POCKETFFT/_CATCH2` 指本地
源码（本次施工即如此），CI 无需该覆盖。升级依赖 = 改 `cmake/dependencies.cmake` 里的固定 tag。

## 6. Fallback 触发条件（何时退 Rust + Tauri）

- M2 性能红线不达标：1280×720 连续 500 帧平均帧间 > 40ms 或 RSS 随帧增长（泄漏）；
- M1 真机 UDP/串口对接出现 Qt 层无法绕过的硬伤（如 QSerialPort 在目标平台不可用）且无替代；
- 任一里程碑出现「C++ 侧修复成本显著高于重写」的架构级问题。
触发即停，走上一版工单 `archive-268-v2-*` 的 Rust + Tauri 方案，C++ 代码归档 `archive/cpp-spike/`。

## 7. go/no-go 结论

**GO**——三项 spike 验收全绿（Ubuntu 编译一项由 Windows 等价验证 + CI 就绪补位），按 C++20 +
Qt6 继续 M1（协议层：serial/udp transport + SourceManager 多收单发）。
