# 2026-11-27 · A-1.5 定因：状态回读失败是**假电台没有应答器**，不是 app 缺陷

## 结论先说

手机端「建流成功、CI-V 上行 7648 帧、界面 0.000000 MHz / 回帧活性=降级」的现象，
**根因在台架而不是客户端**：`fake_rsba1_server` 从不自动回 CI-V。环回用例
（`test_rsba1_loopback`）与 `fake_rig --selftest` 都是**测试自己调 `srv.sendCiv()`
塞一条预置应答**，服务端本身没有「电台模型」。所以真客户端在真网络上轮询时，
上行帧会被计数，但永远没有回帧——任何 app 都不可能显示状态。

## 证据链

1. `03-ledger.png`：手机台账「回帧活性 = 降级：这条链路至今没给过一个能解析的回帧」。
2. 假电台退出小结（上一轮 `evidence/2026-11-22-k40-lan/`）：`serial open: yes`、CI-V 上行 7648 帧。
3. 桌面最小探针（与 app 同一份 `Rsba1UdpTransport`）打旧 fake_rig：`frames=0/40`——
   **同一失败在桌面复现**，排除安卓网络因素。
4. 服务端源码：CI-V 只 `civ_frames_.push_back()`，没有任何自动应答路径；
   `sendCiv()` 仅由测试/selftest 调用。

## 修复（本轮）

`tools/fake_rig.cpp` 增加**最小电台模型**（nominal 及所有非 nak 场景）：
在主循环里 `drainCivFrames()`，按请求命令回 **tests/fixtures 的真机抓包原文**：

| 请求 | 应答（fixture 原文） |
|---|---|
| `0x03` 读频率 | `FE FE 00 A4 03 00 00 27 14 00 FD` → 14.270000 MHz |
| `0x04` 读模式 | `FE FE 00 A4 04 05 01 FD` → FM / filter 1 |
| `0x1C 0x00` 读 PTT | `FE FE 00 A4 1C 00 00 FD` → RX |
| `0x1A 0x03` 读 S 表 | `FE FE 00 A4 1A 03 78 FD` → S9 |

自己拼「看起来像」的帧会被会话层静默丢弃（第一次尝试 `0x03 00 50 14 27 00` 就是
这个下场：回帧计数 0），所以必须用真机抓包原文。

## 验证

- 修复后最小探针（真 UDP，本机环回，40 次读频率）：**frames = 39/40**（11 字节 = 频率应答）。
- 手机 UI 级验收（频率变 14.270000 / 台账回帧活性=可用）**待设备**：
  本轮验证时手机再次从 USB 掉线，`adb devices` 空。
